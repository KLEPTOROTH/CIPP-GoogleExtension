## Blocking threads and implementation contract

1. `apps/api/functions/actions/suspend.ts` (empty body parsing)
- Problem: `req.json()` rejects empty POST bodies even when all request-body fields are optional/defaultable.
- Required behavior:
  - Empty request body must be treated as `{}`.
  - Invalid JSON must still return `INVALID_REQUEST` with status 400.
  - Existing typed validation path (`parseBody`) must remain authoritative.

2. `apps/api/src/cipp/store.ts` (`drainWebhookEvents` claim ownership)
- Problem: drain logic rescans full `webhookEvents` map for `processing`, which can include events claimed by other in-flight drains.
- Required behavior:
  - Process only events claimed in the current drain pass.
  - Preserve idempotency and retry semantics for failed dispatch.
  - Avoid full-map ownership ambiguity in concurrent scenarios.
- Recommendation: build a local `claimed[]` list during the claim loop and process only that list.

## Trust boundaries and failure handling

- API request boundary:
  - Treat transport parse failures separately from schema/typed validation failures.
  - Never conflate empty-body transport with malformed JSON.
- In-memory queue boundary:
  - Drain pass must own only records it transitions to `processing`.
  - State transition authority must be explicit: `received -> processing -> dispatched|failed` for only locally claimed records.
